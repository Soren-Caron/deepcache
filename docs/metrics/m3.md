### A real bug this caught: `.env` was never being read

`backend/.env` existed, with a secret matching
`src/server/config/Backend.luau`. Nothing in the repository actually loaded
it — no `dotenv` import anywhere. The backend was booting on its own built-in
fallback secret (`dev-insecure-ingest-secret`), which did not match the
game's, so **every signed batch was failing verification**, and the failure
presented as `HttpError: ConnectFail` / a breaker opening — indistinguishable
from a genuinely unreachable backend. This is the exact failure mode the
HMAC module's own comments warn about: a signature mismatch that looks like a
network problem instead of an auth bug.

Root-caused by checking, directly, what secret a fresh process actually
loaded:

```
npx tsx -e "loadConfig().ingestSecret"
"dev-insecure-ingest-secret"          <- before the fix, wrong
"dev-ingest-secret-change-me"         <- after adding dotenv, matches Backend.luau
```

Fixed by loading `dotenv` once in `config.ts` rather than requiring every
entry point to remember it. Verified by the live-session flush above landing
with `dropped=0` immediately after the fix. For comparison, `tasks/BACKLOG.md`'s
M3-2 entry records what a *genuinely* unreachable backend looks like from the
same diagnostics bridge — `HttpError: ConnectFail`, failures climbing 2 → 3,
the breaker opening for 60s — which is visually almost identical to what a
wrong secret produces. The two failure modes have to be told apart by reading
`lastError`, not by the symptom.
